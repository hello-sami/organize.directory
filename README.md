# The Organize Directory

A static directory of mutual aid networks and grassroots groups, organized by city, state, and topic. Live at <https://organize.directory>.

## Where things stand (as of 2026-11-17)

- **Live and working:** 337 city pages, 52 state/region pages, 41 topic pages, 2,625 listings. The Phone Book redesign (Oct 2026) is finished and live.
- **Listings have been fact-checked** (Sept–Oct 2026): dead links, closed groups, boilerplate descriptions and the page structure were all reviewed and fixed.
- **Not done:**
  - 7 pages have no listings: `rock-hill`, `topeka`, `hawaii-island`, `kauai`, `charleston-wv`, `south-al`, `sierra`. They were kept on purpose as invitations to add groups.
  - About 17 listings have no description (Instagram-only, couldn't be verified), and about 900 Instagram/Facebook-only listings can't be checked automatically.
  - Five groups look inactive but were left in because it wasn't confirmed: CARES Free Store, FNB Fort Wayne, South Bay Mutual Aid, LGBTQ+ of Mobile Bay, Durango Peace & Justice.
  - "See also" related-topics links aren't built (they need data first).
  - `_headers` has a `/*.html` caching rule that never takes effect, because Pages serves pages without `.html`. Live HTML is `max-age=0, must-revalidate`. Whether to change that is a freshness-vs-speed choice (it affects how fast CMS edits show up).
- **Not pushed:** check `git status` / `git log origin/main..HEAD`. A push deploys.

## Starting it up again

```bash
npm install
npm run dev      # preview the site at http://localhost:8788 (needs Wrangler, see below)
```

To edit content, use the local CMS (see "Local CMS" below) or edit `data/*.json` by hand and run `npm run build`.

## How it works

The site is a static HTML build deployed to Cloudflare Pages. Content lives in JSON; pages are generated by `scripts/build.js` and committed to the repo.

```
data/
├── locations/        # one JSON file per city  → cities/<slug>.html
├── states/           # one JSON file per state → states/<slug>.html
├── topics/           # one JSON file per topic → topics/<slug>.html
├── redirects.json    # hand-edited: slug of a retired/merged page → slug it moved to
│                     #   (build turns these into rules in _redirects)
├── stats.json        # written by build: group / city / category counts
└── title-index.json  # written by build: page titles (not read by the live site;
                      #   the search box reads js/title-index.json instead, see below)
scripts/
├── build.js              # JSON → HTML (incl. index.html), sitemap, robots, _redirects,
│                         #   stats; content-hashes CSS/JS (?v=…) and keeps the head,
│                         #   header bar of the hand-maintained pages in sync
├── check-links.js        # read-only link checker for every website link in data/
│                         #   (see "Checking links" below)
├── make-paper.js         # one-off: regenerates the paper show-through images
└── migrate.js            # legacy, one-time: turned the old hand-written HTML into
                          #   data/*.json. Don't run it now: it would overwrite the JSON
assets/
├── styles/system.css   # Single source of truth for all styling (+ @font-face)
├── scripts/            # city-page.js (thumb notches, guide words, filter)
├── paper/              # grain.svg + ghost-{yellow,white}.svg (the thin-paper look)
└── fonts/              # Self-hosted IBM Plex Sans Condensed (woff2, SIL OFL)
js/
├── title-search.js          # the header search box; loads js/title-index.json
├── title-index.json         # the search index, written by generate-titles-index.js
├── generate-titles-index.js # builds js/title-index.json (run: npm run generate-title-index)
└── analytics.js
_headers          # Cloudflare Pages CSP, caching, security headers
_redirects        # Generated by build: bare-slug → /cities/<slug> (no .html, so Pages rewrites instead of redirecting)
```

Also in the repo: the built pages (`cities/`, `states/`, `topics/`, `index.html`,
`sitemap.xml`, `robots.txt`), the hand-maintained pages listed below, and the favicon
and logo files. `dist-preview/` (from `build.js --preview`), `.cache/` and `_cms/` are
local-only and gitignored, so a fresh clone won't have them. So are `design-mockups/` and `design-system.html` (design exploration; `design-mockups/MIGRATION-PLAN.md` is an out-of-date plan from the redesign, kept only as history).

Fonts are self-hosted (latin subset) and declared via `@font-face` in
`system.css` — there is no Google Fonts request. CSS/JS are served `immutable`
for a year and cache-busted by a `?v=<contenthash>` the build injects, so an
edited asset is re-fetched while unchanged ones stay cached.

## Design

The site is built like a phone book. Place pages (cities, states, `/location`)
are the **Local Listings**, on grey newsprint (a phone book's white pages);
issue pages (topics, `/topics`) and the homepage cover are the **Issue
Listings**, on faded yellow (its yellow pages). A body class
(`white` / `yellow`) picks the paper. Every page has faint paper grain and a
mirrored page of listings showing through, both dropped for visitors whose
system asks for more contrast. The logo is a thumb notch (a D) with a punched
hole (an O); the same notch marks the section you're reading down the left
edge of list pages. There is no dark mode.

Hand-maintained pages: `location.html`, `topics.html`, `guides.html`, `add.html`, `404.html`. (`index.html` is generated.)

## Local development

```bash
npm install
npm run build                  # regenerate cities/, states/, topics/, sitemap, _redirects, stats
npm run dev                    # wrangler pages dev — serves locally with Pages semantics
npm run generate-title-index   # rebuild the search index (after adding/removing pages)
node scripts/check-links.js    # check every website link (see "Checking links")
```

`npm run build` also takes `--dry-run` (print counts, write nothing) and `--preview`
(build into the gitignored `dist-preview/` instead of the live folders):
`node scripts/build.js --dry-run`, `node scripts/build.js --preview`.

`generate-title-index` reads the built `cities/`, `states/` and `topics/` HTML, so run
`npm run build` first, then it. It writes `js/title-index.json`.

There is no separate dev server — `wrangler pages dev` serves the static files plus `_headers` and `_redirects`. Wrangler is not in `package.json`; it's installed globally on this Mac (`/opt/homebrew/bin/wrangler`). On a new machine, run `npm i -g wrangler`. If it refuses the compatibility date, use an older one.

## Adding a group

1. Open the relevant `data/locations/<city>.json` (or create a new one — copy an existing file such as `data/locations/albany.json` for the schema: `slug`, `title`, `state`, `parent`, `sections`).
2. Add an entry under the matching section's `initiatives` array: `{ "name": ..., "url": ..., "description": ... }`. An optional `links` array holds extra links, like `{ "type": "instagram", "url": ... }`.
3. Run `npm run build`, then `npm run generate-title-index` if you added a new page.
4. Commit JSON + regenerated HTML.

## Checking links

`scripts/check-links.js` finds dead or changed website links. It is **read-only**: it
never edits anything in `data/`. It needs only Node (no `npm install` packages) and
an internet connection.

```bash
node scripts/check-links.js            # check every link, write a report (takes a while)
node scripts/check-links.js --recheck  # re-test only what was flagged last time (fast)
node scripts/check-links.js --help
```

It checks each listing's main `url`, plus any `links` entry of type `website`, in
`data/locations`, `data/states` and `data/topics`. It skips Instagram, Facebook,
X/Twitter, Bluesky, TikTok, LinkedIn and Threads, because those sites block automated
visitors and their answers can't be trusted.

Results are written to `.cache/link-check/` (gitignored, created on first run):

- `report.md` — the short list to read, grouped by state / city / topic page, with the data file to fix
- `results.json` — every URL checked and its status, for digging deeper

Each flagged link is labelled `dead` (404/410 or no response), `suspicious` (server
error, can't connect, or looks like a parked or expired domain), `redirect-offsite`
(now goes to a different site) or `redirect-home` (a deep page now lands on the home
page). `blocked` links (the site refused the script) are counted but not listed.
`--recheck` needs a previous run's `results.json`; without one it does a full check.

To fix a flagged link, edit the JSON file named in the report by hand, then run
`npm run build` and commit as usual.

## Local CMS

`_cms/` is a small editor for the listings. It is gitignored, never deployed, and a fresh clone won't have it.

- **Start:** double-click `_cms/Launch Organize CMS.command` (or run it in a terminal). It serves on <http://localhost:8763> and installs its own dependencies the first time.
- **What it does:** every edit changes `data/`, rebuilds, and commits the data plus the built pages. It does not push. Its **Publish** button pushes, and that deploys, so it also ships any other unpushed commits.
- `_cms/tools/backfill/` holds the scripts used for the fact-checking rounds. Its data lives outside the repo, in `~/.misen-data/organize-cms/`.
- Keep design/code changes committed, never half-done in the working tree: a CMS commit would pair new pages with an old stylesheet.

## Contact

There's no contact page, contact form or newsletter (all removed 2026-10-29). The add-a-group page gives an email address, and `/contact` redirects there; `/subscribe` and `/thank-you` redirect home.

## Deployment

Pushed to `main` → Cloudflare Pages deploys the repo root **exactly as committed — it does not run the build**. So the regenerated HTML has to be committed alongside the JSON; a push of `data/` alone changes nothing on the live site. The local CMS (`_cms/`, gitignored) does this automatically: after each edit it rebuilds and commits `data/` plus the build output (`cities/`, `states/`, `topics/`, `index.html`, `sitemap.xml`, `_redirects`, `robots.txt`).
