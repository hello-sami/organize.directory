# The Organize Directory

A static directory of mutual aid networks and grassroots groups, organized by city, state, and topic. Live at <https://organize.directory>.

## How it works

The site is a static HTML build deployed to Cloudflare Pages. Content lives in JSON; pages are generated by `scripts/build.js` and committed to the repo.

```
data/
├── locations/    # one JSON file per city  → cities/<slug>.html
├── states/       # one JSON file per state → states/<slug>.html
└── topics/       # one JSON file per topic → topics/<slug>.html
scripts/
├── build.js      # JSON → HTML (incl. index.html), sitemap, robots, _redirects,
│                 #   stats; content-hashes CSS/JS (?v=…) and keeps the head,
│                 #   header bar and footer of the hand-maintained pages in sync
├── make-paper.js # one-off: regenerates the paper show-through images
└── ...
assets/
├── styles/system.css   # Single source of truth for all styling (+ @font-face)
├── scripts/            # city-page.js (thumb notches, guide words, filter)
├── paper/              # grain.svg + ghost-{yellow,white}.svg (the thin-paper look)
└── fonts/              # Self-hosted IBM Plex Sans Condensed (woff2, SIL OFL)
js/                     # title-search.js, analytics.js, newsletter-form.js
_headers          # Cloudflare Pages CSP, caching, security headers
_redirects        # Generated by build: bare-slug → /cities/<slug>.html
```

Fonts are self-hosted (latin subset) and declared via `@font-face` in
`system.css` — there is no Google Fonts request. CSS/JS are served `immutable`
for a year and cache-busted by a `?v=<contenthash>` the build injects, so an
edited asset is re-fetched while unchanged ones stay cached.

## Design

The site is built like a phone book. Place pages (cities, states, `/location`)
are the **Local Listings**, on grey newsprint (a phone book's white pages);
issue pages (topics, `/topics`) and the homepage cover are the **Issue
Listings**, on faded yellow (its yellow pages). A body class
(`white` / `yellow`) picks the paper. Every page has faint paper grain and a
mirrored page of listings showing through, both dropped for visitors whose
system asks for more contrast. The logo is a thumb notch (a D) with a punched
hole (an O); the same notch marks the section you're reading down the left
edge of list pages. There is no dark mode.

Hand-maintained pages: `location.html`, `topics.html`, `guides.html`, `contact.html`, `subscribe.html`, `thank-you.html`, `add.html`, `404.html`. (`index.html` is generated.)
Subscribe is paused for now: `subscribe.html` stays in the repo but nothing
links to it, and `/subscribe` redirects home (see the note above `NAV_MENU` in
`scripts/build.js` for how to bring it back).

## Local development

```bash
npm install
npm run build                  # regenerate cities/, states/, topics/, sitemap, _redirects, stats
npm run dev                    # wrangler pages dev — serves locally with Pages semantics
npm run generate-title-index   # rebuild the search index (after adding/removing pages)
```

There is no separate dev server — `wrangler pages dev` serves the static files plus `_headers` and `_redirects`.

## Adding a group

1. Open the relevant `data/locations/<city>.json` (or create a new one — see existing files for the schema).
2. Add an entry under the matching section's `initiatives` array: `{ "name": ..., "url": ..., "description": ... }`.
3. Run `npm run build`, then `npm run generate-title-index` if you added a new page.
4. Commit JSON + regenerated HTML.

## Contact form

Submissions are POSTed directly to [Web3Forms](https://web3forms.com/) from the browser using the access key embedded in `contact.html`. There's no server-side handler. A `botcheck` honeypot field filters bots.

## Deployment

Pushed to `main` → Cloudflare Pages deploys the repo root **exactly as committed — it does not run the build**. So the regenerated HTML has to be committed alongside the JSON; a push of `data/` alone changes nothing on the live site. The local CMS (`_cms/`, gitignored) does this automatically: after each edit it rebuilds and commits `data/` plus the build output (`cities/`, `states/`, `topics/`, `index.html`, `sitemap.xml`, `_redirects`, `robots.txt`).
